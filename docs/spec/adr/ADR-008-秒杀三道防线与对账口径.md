# ADR-008 秒杀：三道防线与对账口径

- 状态：已接受（对应 PRD D8/D16）
- 日期：2026-11-17（2026-11-18 复审 N1/N8 修订）

## 决策

- 范围：秒杀商品 = 充值包 + 普通商品（履约按类型分派）；
- 活动库存独立于 goods.stock（预热进 Redis，`redis_key` 记录于活动表）；
- 三道防线：① Redis Lua 原子「判重+判库存+扣减」快速失败；② DB 落库 `sold_stock` 条件更新兜底；③ `UNIQUE(activity_id, tenant_id)` 防重复抢购；
- 削峰：扣减成功 → Kafka(seckill.orders)（voucher=order_no 由 seckill 服务**预生成**并随消息传递）→ produce 后同步返回「排队中+凭证」→ 消费者落库建单；
- 超时 15 分钟未支付：延迟任务回补 Redis 库存（幂等：仅 status 成功转 timeout 时回补）——**对账处置中唯一的自动回补场景**（普通订单超时/取消/退款的库存回补属订单状态机常规动作，不在对账口径内）；
- 对账 job：Redis 余量 vs DB（sold_stock+在途）比对，不一致记录差异，滞留**默认保留待核查**（沿用 reconciler `-no-auto-reverse` 默认口径），不自动回滚。

## 理由

- 与 billing 预扣同构（Lua 原子判断+扣减），一套模式多处落点；
- reconciler 的"默认保留"是既有安全口径，秒杀不擅自放宽；
- Kafka at-least-once 下消费者以唯一索引幂等。

## 后果

- "排队中"语义要求 App 轮询凭证状态（不做推送）；
- 对账差异需要人工出口（管理端查询/日志）。
