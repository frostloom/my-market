# ADR-010 mall 侧稳定性：三板斧与限流三层

- 状态：已接受（对应 PRD D12；N11 补落点）
- 日期：2026-11-18

## 决策

**三板斧**（不引入服务间熔断框架）：
1. 超时预算分层：mall-bff 聚合 5s；服务间 gRPC 1-2s；Credit/ActivateSubscription 3s 指数退避重试×3（幂等安全）；
2. 重试：仅幂等操作自动重试（Credit 幂等、查询无副作用）；非幂等一律幂等键保护；
3. 对账兜底：履约滞留/秒杀在途由对账 job 三分类处置（默认保留待核查）。

**限流三层**：
| 层 | 对象 | 机制 | 落点 |
|---|---|---|---|
| 数据面 | /v1 推理 | billing 既有 Redis Lua（不动） | gateway |
| 秒杀入口 | 抢购端点 | 令牌桶（R4 压测定容）→ MALL_40004 | mall-bff/seckill |
| 基础 | per-tenant 全接口 | Redis 计数器 120 req/min → MALL_10006 | mall-bff 中间件 |

## 理由

- 上游（LLM）熔断 router 已有（内存模式 5 连败 / Redis 模式 60s 窗口 20 次 + AutoBan 持久化）；mall 内部规模下服务间熔断收益低于复杂度；
- "超时+重试+对账"组合可覆盖本体系全部已知故障路径（worker 崩溃、billing 闪断、消息重复）。

## 后果

- billing 长时间宕机时表现为订单停留 paid + 503（MALL_50003），由对账收敛——接受最终一致；
- 熔断状态机多副本共享为 P1 待决策（失败计数已共享，仅状态机每实例内存）。
