# ADR-001 整仓迁移与 go.work 双模块布局

- 状态：已接受（对应 PRD D1）
- 日期：2026-11-17
- 关联：ADR-005、ADR-006

## 背景

ai-gateway 是已完成的独立 Git 仓（.git 2.6G、eval/ 220M），商城需要与其融合为单一体系。备选：subtree 吸收 / 双仓集成 / 整仓迁入同仓双模块。

## 决策

整仓迁入 `my-market/ai-gateway/`：迁源码/web/docs/scripts/deploy/eval（评测与 langfuse 后续在新仓继续）；不迁 .git 历史、logs、.gocache。根模块 `github.com/frostloom/my-market` + 嵌套模块 `github.com/frostloom/ai-gateway`（模块路径不变，import 零改动），go.work 串联。旧仓 GitHub 归档只读并指向新仓。

## 理由

- 2.6G 历史与商城运行时无关，拖累 clone；
- 模块路径不变使 gateway 代码零改动即编译，迁移风险最低；
- 一个仓库讲完"计费内核 → 商城 → 云原生"完整故事，面试叙事最强；
- "双开发"诉求以"同仓两模块区"满足：gateway 目录内继续演进不受商城影响。

## 后果

- 旧仓停止演进（历史与评测报告的可信度凭证保留在归档仓）；
- CI 需同时构建两模块；评测产物使新仓体积增加约 220M（接受）。
