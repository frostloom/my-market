### 7.2 r26-canonical 机制（为何字节敏感）

`canonical_code_bytes()` = 读自身文件字节 → 剥离哨兵块 → 逐条执行 MIGRATION_LINES
反向改写（`migrated`（现形态）→`frozen`（R2.6 前形态））→ 得到"前布局原文"，与冻结
manifest 的 generator/exporter sha256 比对。推论：

1. **哨兵块内的任何增改不影响 canonical 字节**（先剥离）——但 MIGRATION_LINES 每条的
   `migrated` 必须在剥离后文本中逐字节存在，否则 ValueError。
2. **哨兵块外的任何行改动都会进入 canonical 文本** → 必须同时在 MIGRATION_LINES **表头**
   （列表最前，先于 R2.6 条目执行）登记 `(新行, R2.6 形态行)` 反向改写，形成
   `R2.7 形态 → R2.6 形态 → R2.6 前形态` 的两段还原链。表体在块内，条目本身不进 canonical 字节。
3. 运行时真正生效的是块外的**新形态行**；哈希还原线与运行线并行，互不干扰。

### 7.3 统一锚定事实（全部 22 个 .py 相同）

```python
ROOT = Path(__file__).resolve().parents[1]                        # scripts/ 的上一级
EVAL = ROOT.parent.parent / 'eval' / 'ai-gateway'                 # 15 个脚本有此行
```

即：**脚本所在目录深度必须=仓库根下 2 层**（`repo/A/B/脚本.py`，parents[1]=repo/A/B，
parents[1].parent.parent=repo）时，EVAL 行字节不动即语义正确。现位 services/ai-gateway/scripts/ 即此深度。

ROOT 的运行期消费面（块外、非 eval/ 前缀）仅 4 处：
1. customer-service-contract.py:138 `generator = ROOT / 'web/scripts/gen-intent-suite.mjs'`（normalization_proof）
2. customer-service-contract.py:381 export sources 列表同一路径
3. customer-service-contract.py:408 verify 含断言 `base = (EVAL if name.startswith('eval/') else ROOT)`（web/ 名走 ROOT 包含判定）
4. audit-historical-answer-evidence.py:71-76 `frozen_source_label`：`path.relative_to(ROOT)` 失败才回退 `'eval/'+relative_to(EVAL)` —— **要求 ROOT 不是 eval/ai-gateway（或其祖先）**，否则标签少 `eval/` 前缀、与冻结记录不一致。

## 10. 风险清单

1. **字节链断裂风险（最高）**：8 个 canonical 钉死脚本任何一个未按 §7 配方迁移 → Windows verify job
   与本地 verify 全红。缓解：git mv（保留字节）+ 迁移后立即本地全量 verify + V3 降级路线。
2. **裁定 A 未决即动工**：store/agent 的安置若先按 internal 执行，agent 服务与 9 个评测 cmd
   编译失败，返工面大。缓解：T2 开工前必须拿到 §11 裁定。
3. **pkg 追加项（jev/observability/supportconfig/upstream/gatewayclient）扩大 mall 可见面**：
   单模块下 pkg/ 对 mall 同样可见，importguard 删除后唯一硬门禁是 internal 规则。缓解：
   T3 恶意导入测试扩展两条（mall→services/billing/store、mall→pkg/jev 等 pkg 新面应视为
   ai 域公共 API 的越界使用——以 CI grep 门禁或轻量守卫测试固化"mall 只许 import
   pkg/proto/billing/v1"的契约），ADR-011 写明公开面清单与守卫方式。
4. **确认清单与事实冲突（xid/quota/kafka/trace）**：按确认清单放 pkg 会把 gateway/billing 专属
   小库公开化；按事实收进服务 internal 则偏离确认清单。两者都编译合法，属治理口径差。
5. **taskbench 白名单字符串（§7.7）被误"同步更新"**：拆分类工具动路径字符串=破坏既有证据校验，
   明确 DO-NOT-EDIT。
6. **web/dist 二次搬迁风险**：dist 由 vite 生成入库；本次只随包 git mv 一次（outDir 行同步），
   不重建（重建=字节漂移+无必要）。
7. **80 基线漂移**：import 重写+依赖版本收敛可能引入 vet/测试行为差异。缓解：门禁①
   失败名集合恒等比对（计划既定）。
8. **seckill 空目录**：仅 README，无 Go 包；services/seckill 保持存在即可，勿删。
9. **AGENTS.md 物理归宿**：taskbench 按文件名引用其历史形态（数据比对），物理位置自由；
   但它同时是 append-only 台账，随意移动会打断 T3 的"活文档旧路径 grep 清零"判断，归置见裁定 F。
