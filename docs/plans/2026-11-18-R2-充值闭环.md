# R2：充值闭环 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 打通商业主线：买充值包 → billing Credit 入账 → gateway /v1 推理扣费 → 流水可见，全程幂等、断电不重不漏。

**Architecture:** billing 侧新增 Credit/Refund 两个幂等 gRPC（复用 topups 同步事务路径，MySQL 提交点、Redis 投影对齐）；proto 从 internal/ 移至 pkg/ 暴露给 mall 模块（go.work 唯一合法 import 面）；mall-order 扩展 recharge 直购与 credit 履约分支；bff 补 kind 路由与 /me/overview。

**Tech Stack:** Go 1.26 · gRPC/protobuf · GORM · go-redis · 既有 compose 全家（11 容器）

**Spec:** [PRD.md](../PRD.md) v0.5 §2/§5.2/§13 · [ADR-005](../spec/adr/ADR-005-billing加法改造Credit与订阅.md)（本计划修订为三处加法）· [api-contract.md](../spec/api-contract.md) §5/§7 · [acceptance.md](../spec/acceptance.md) R2 节

## Global Constraints

- billing **三处加法改造**（Credit、Refund；ActivateSubscription 留 R2.5）：Reserve/Settle/Reverse 语义**零改动**；旧 403 充值端点**不打开**；billing 既有测试必须全绿
- Credit 契约：`Credit(tenant_id, amount_cent>0, ref_type="mall", ref_id)`——复用 `uk_ref(ref_type,ref_id)` 幂等，重复 no-op；Refund 契约：`Refund(tenant_id, amount_cent>0, ref)`——退额=min(请求额,当前余额) 口径、幂等（参照 store.RefundAmount 既有语义）
- mall 模块**唯一允许的 ai-gateway import 面**：`ai-gateway/pkg/proto/billing/v1`（T1 产物）；其余 internal/ 依旧禁止（grep 断言）
- 金额一律 int64 分；ref_id=`order_no:line_no`
- R2 边界：月卡 ActivateSubscription（R2.5）、秒杀（R4）、真实支付 Provider（P5）不碰；/me/overview 本期交付（R1 遗留）
- 环境：CGO_ENABLED=0；compose infra+ai+mall 全家在跑；Kafka 宿主 29092；X-Control-Token 类凭据不入日志不回显

## Review Focus

1. **Credit 幂等矩阵**：正常入账 / 同 ref 重复 no-op / 非正金额拒绝 / 入账后 Redis 余额与 MySQL 一致 → T1 测试
2. **断电不重不漏**：paid+pending credit 履约行，worker 重启收敛，billing topups 恰一条 → T3 专测
3. **import 边界**：mall 全部源码 grep 断言仅 import pkg/proto → T2 静态检查入测试
4. **退款 min 口径**：余额充足全退 / 余额不足部分退 / 重复 ref 幂等 → T3 测试
5. **/me/overview 凭据安全**：控制令牌零泄漏（日志/响应）→ T4 断言
