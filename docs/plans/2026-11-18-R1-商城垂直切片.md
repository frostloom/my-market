# R1：商城垂直切片 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** mall-goods/mall-order/mall-bff 三服务落地：品类/游标分页商品/购物车/general 下单支付（mock 异步回调）/outbox 发货履约/超时取消，REST 全端点按契约，错误模型与限流就位。

**Architecture:** mall 三服务为根模块新代码，gRPC 互通，market 库（MySQL 3307 同实例）；下单与支付状态机在 mall-order（同步事务 + outbox），mall-bff 只做协议转换/鉴权/限流；不 import ai-gateway 任何包（其代码全在 internal/ 下，跨模块不可达），billing 依赖从 R2 才开始。

**Tech Stack:** Go 1.25 · gin · gRPC+protobuf · GORM(MySQL) · go-redis/v9（与 ai-gateway 同栈）

**Spec:** [PRD.md](../PRD.md) §5/§7/§8 · [api-contract.md](../spec/api-contract.md) · [db-schema.sql](../spec/db-schema.sql) · [sequences.md](../spec/sequences.md) 图1/2/6 · [acceptance.md](../spec/acceptance.md) R1 节 · ADR-002/004/007/009

## Global Constraints

- 金额一律 `int64` 分；时间 UTC 存 `DATETIME(3)`；表结构以 db-schema.sql 为准，不自创字段
- 错误体恒为 `{"error":string,"code":string,"retryable":bool}`；码表=api-contract §1，常量定义于 `pkg/mallerr`
- 幂等键作用域 `(tenant_id, idem_key)`；游标=(created_at,id) 键集降序 Base64
- **禁止 import `github.com/frostloom/ai-gateway/**`**（internal 隔离）；R1 无 billing/Kafka 依赖
- mall-order 对 goods 表的同库直写仅限 `stock` 条件更新（ADR-009）
- R1 边界：退款只实现 `paid→refunded`（作废 pending 行）；`fulfilled` 退款/冲退、recharge 直购、秒杀是 R2/R4；月卡是 R2.5；`/me/overview` 端点 R2 交付（需 billing proto 跨模块暴露，与 Credit 同批处理，见 ADR-005/006）
- 每个 HTTP 写端点必有 gRPC 幂等或唯一索引兜底；proto 一次定义（Task 2），后任务只消费

## Review Focus

1. **幂等键跨租户串号**：A 租户与 B 租户用同一 idem_key 各自成单互不干扰 → 测试落 Task 4 `TestCreateOrder_IdemKeyScopedPerTenant`
2. **游标被篡改/垃圾值**：非法 Base64 或不存在键 → 返回 MALL_10005 而非 500 → Task 3 `TestDecodeCursor_Garbage`
3. **回调重放改金额**：同单第二次回调金额不同 → 以首次为准 no-op（订单状态不变、流水不新增）→ Task 5 `TestMarkPaidTx_DuplicateCallbackDifferentAmount`
4. **并发抢最后一件库存**：两事务同扣最后 1 件，恰一成一败（条件更新影响行数）→ Task 4 `TestCreateStock_InsufficientRollback` + 并发版
5. **越权访问**：租户 A 查/退租户 B 的订单 → 视为不存在（404/MALL_30001）→ Task 6 `TestOrderAccess_TenantIsolation`
